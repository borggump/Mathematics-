Why Quantum Emulators Hit a Wall

State vectors, Matrix Product States, and the math behind MIMIQ's approach

The press release describes MIMIQ as pairing state-vector emulation with Matrix Product State (MPS) techniques. This page builds that idea from the ground up. The release does not publish MIMIQ's internal algorithms, so the math below is the general method, not a description of MIMIQ's exact code.

1. The problem: qubits double the state

A classical computer must store the full quantum state of \(n\) qubits. A general pure state is a vector of \(2^n\) complex amplitudes:

$$|\psi\rangle = \sum_{s_1,\dots,s_n \in \{0,1\}} c_{s_1 s_2 \dots s_n}\, |s_1 s_2 \dots s_n\rangle, \qquad \sum |c_{s}|^2 = 1$$

Each complex amplitude in double precision takes 16 bytes, so the memory needed is:

$$M_{\text{SV}}(n) = 16 \cdot 2^n \ \text{bytes}$$

Each added qubit doubles the memory. This is the "memory wall" the press release refers to when it says standard simulators hit a limit at a few dozen qubits.

Cost of a gate

A single-qubit gate \(U\) acting on qubit \(k\) updates every amplitude pair:

$$\begin{pmatrix} c'_{\dots 0 \dots} \\ c'_{\dots 1 \dots} \end{pmatrix} = U \begin{pmatrix} c_{\dots 0 \dots} \\ c_{\dots 1 \dots} \end{pmatrix}$$

That touches all \(2^n\) amplitudes, so the time per gate is \(O(2^n)\) as well.

2. The key observation: not every state is complicated

The state vector stores every possible correlation, but real circuits often create only limited correlations. The tool for measuring how correlated one part of the system is with the rest is entanglement.

Schmidt decomposition across a cut

Split the qubits into a left group \(A = \{1,\dots,k\}\) and a right group \(B = \{k+1,\dots,n\}\). Any pure state can be written as

$$|\psi\rangle = \sum_{a=1}^{r} \sigma_a\, |\alpha_a\rangle_A \otimes |\beta_a\rangle_B$$

where \(\sigma_a \ge 0\) are the Schmidt coefficients (the singular values), \(\{|\alpha_a\rangle\}\) and \(\{|\beta_a\rangle\}\) are orthonormal sets, and \(r\) is the Schmidt rank. Normalization requires \(\sum_a \sigma_a^2 = 1\).

  • If \(r = 1\), the state is a product across the cut: \(|\psi\rangle = |\alpha\rangle \otimes |\beta\rangle\). No entanglement.
  • If \(r\) is large, the two halves are strongly entangled, and a simple description is hard.

The entanglement entropy across the cut is

$$S_k = -\sum_{a} \lambda_a \log_2 \lambda_a, \qquad \lambda_a = \sigma_a^2$$

with \(S_k \le \min(k,\, n-k)\) bits.

3. Matrix Product States (MPS)

An MPS writes the \(2^n\) amplitudes as a chain of small matrices. Each site \(i\) gets a rank-3 tensor \(A^{[i]s_i}\) with a physical index \(s_i \in \{0,1\}\) and two virtual (bond) indices:

$$c_{s_1 s_2 \dots s_n} = A^{[1]s_1}\, A^{[2]s_2} \cdots A^{[n]s_n}$$

Here each \(A^{[i]s_i}\) is a \(\chi_{i-1} \times \chi_i\) matrix, so the amplitude is a product of matrices, which is a scalar. The bond dimension \(\chi\) is the largest bond size:

$$\chi = \max_i \chi_i, \qquad \chi_0 = \chi_n = 1$$

Memory cost

Each site stores \(2\) matrices of size up to \(\chi \times \chi\), so

$$M_{\text{MPS}}(n,\chi) \approx 16 \cdot 2\, n\, \chi^2 \ \text{bytes}$$

This grows linearly in \(n\), not exponentially. The catch is that \(\chi\) must be large enough to represent the state.

4. Connecting entanglement to bond dimension

The bond dimension \(\chi_k\) across the cut between sites \(k\) and \(k+1\) must be at least the Schmidt rank \(r_k\) of that cut. If it is, the MPS is exact:

$$\chi_k \ge r_k \quad \Longrightarrow \quad \text{MPS representation is exact at this cut}$$

Since \(r_k \le 2^{\min(k,\,n-k)}\), the worst case needs \(\chi \approx 2^{n/2}\) at the middle of the chain, which is exponential again. The MPS method is efficient only when entanglement stays low, which is what the press release means by "as long as entanglement stays limited."

Why GHZ is cheap

The GHZ state has only two terms. Across any cut, the left part is either all 0s or all 1s, so the Schmidt decomposition has exactly two terms with \(\sigma_1 = \sigma_2 = 1/\sqrt{2}\):

$$|\text{GHZ}\rangle = \frac{1}{\sqrt{2}}\,|0\dots0\rangle_A|0\dots0\rangle_B + \frac{1}{\sqrt{2}}\,|1\dots1\rangle_A|1\dots1\rangle_B$$

So \(\chi = 2\) works at every cut, and the MPS needs about \(n \cdot 2 \cdot 2 \cdot 2 \cdot 16\) bytes whether \(n\) is 30 or 3,000. The state vector would need 16 GiB at \(n=30\) and far more beyond that.

7. Applying a two-qubit gate to an MPS

Two-qubit gates are where the MPS has to work. Suppose a gate \(U\) acts on neighboring sites \(k\) and \(k+1\). The procedure has four steps.

  1. Merge the two tensors into one: $$\Theta^{s s'}_{ab} = \sum_{c} A^{[k]s}_{ac}\, A^{[k+1]s'}_{cb}$$ This is a \(\chi \times \chi\) matrix for each of the \(2 \times 2\) physical pairs.
  2. Apply the gate to the physical indices: $$\Theta'^{t t'}_{ab} = \sum_{s,s'} U_{t t',\, s s'}\, \Theta^{s s'}_{ab}$$
  3. Split by singular value decomposition. Reshape \(\Theta'\) into a \((2\chi)\times(2\chi)\) matrix \(M\), then $$M = U_{\text{sv}}\, S\, V^\dagger, \qquad S = \text{diag}(\sigma_1 \ge \sigma_2 \ge \dots)$$
  4. Truncate to the largest \(\chi\) singular values and absorb \(S\) into one side: $$A^{[k]} \leftarrow U_{\text{sv}}[:, 1..\chi], \qquad A^{[k+1]} \leftarrow \big(S V^\dagger\big)[1..\chi, :]$$

Step 4 is where information can be lost. If the discarded singular values are not zero, the result is only an approximation.

Truncation error

With a normalized state, the weight thrown away at one truncation is

$$\varepsilon_k = \frac{\sum_{a > \chi} \sigma_a^2}{\sum_{a} \sigma_a^2}$$

Across a whole circuit, these per-gate losses add up. A standard bound is that the infidelity of the approximate state is roughly at most the sum of all discarded weights:

$$1 - F \;\lesssim\; \sum_{\text{gates } g} \varepsilon_g$$

This is why the release mentions "controlled truncation error." Users choose \(\chi\) or a truncation threshold and get a known error budget.

Example: truncating a state

Take singular values \(\sigma = (0.8,\ 0.5,\ 0.3,\ 0.1,\ 0.1)\). Check normalization: \(0.64 + 0.25 + 0.09 + 0.01 + 0.01 = 1.00\). Keeping \(\chi = 3\) discards \(0.1\) and \(0.1\), so

$$\varepsilon = 0.01 + 0.01 = 0.02 \quad (2\%)$$

8. Cost of the MPS method

OperationApproximate cost
Storage\(O(n\,\chi^2 d)\), with \(d=2\)
One two-qubit gate (merge + SVD)\(O(\chi^3 d^3)\)
Full circuit with \(G\) gates on \(n\) qubits\(O(G\,\chi^3)\), with no \(2^n\) factor
Exact state-vector gate\(O(2^n)\)

The gate cost does not depend on \(n\), so the MPS method scales well in qubit count and in gate count. The cost depends on \(\chi\). When entanglement grows, \(\chi\) must grow, and the cost grows as \(\chi^3\). That is the limit on the "subject to the limits of the simulation method" caveat in the release.

9. Why combine the two methods?

Neither method is best everywhere. Exact state vectors are accurate, but limited to a few dozen qubits. MPS handles many qubits, but only while entanglement is low. A hybrid or threshold approach lets the emulator choose the representation and error budget for each circuit.

RegimeBetter methodReason
Small \(n\) (up to roughly 30 qubits), any entanglementState vectorExact, no truncation error
Large \(n\), low entanglementMPSMemory is linear in \(n\)
Large \(n\), high entanglement (deep random circuits)Neither is cheap\(\chi\) grows exponentially with the cut size

10. Summary

  • A state of \(n\) qubits needs \(2^n\) amplitudes. Memory is \(16 \cdot 2^n\) bytes.
  • An MPS stores the state as a chain of tensors with bond dimension \(\chi\). Memory is about \(32\,n\,\chi^2\) bytes.
  • The MPS is exact when \(\chi\) is at least the Schmidt rank across every cut. Schmidt rank is controlled by entanglement.
  • Gates are applied by merging, multiplying by the gate, then splitting with SVD and truncating to \(\chi\). Truncation discards weight \(\varepsilon\), which adds up over gates.
  • MIMIQ, per the press release, combines state-vector and MPS methods so that circuits up to thousands of qubits can be emulated, with the accuracy limited by entanglement and truncation.

Note: the scaling numbers and the worked example are illustrative. Any real emulator's accuracy claims should be checked against independent benchmarks.
